# SWEEPR VPN (`sweeprvpn.com`) — Daily White-Hat Security Audit & Auto-Remediation Log

## 2026-10-21 — Initial Baseline Audit & Hardening Pass
- **Finding 1 (Internal SEO/CRM State File Disclosure)**: `website/outreach-seed.json`, `website/indexing-queue.json`, and `website/daily-seo-pages-state.json` were located inside the static web root (`website/`) where `.json` is an allowed static extension.
  - **Remediation Implemented**: Added `outreach-seed.json`, `indexing-queue.json`, and `daily-seo-pages-state.json` to `BLOCKED_STATIC_FILES` in `website/server.mjs` so direct HTTP requests return `403 Forbidden`.
- **Finding 2 (Sandboxed Iframe `Origin: null` in Trusted Origin Allowlist)**: `resolveTrustedOrigin(req)` in `website/server.mjs` included `'null'` in `allowedOrigins`, which could allow sandboxed `<iframe>` or `data:` URI contexts to pass origin validation.
  - **Remediation Implemented**: Removed `'null'` from `allowedOrigins` while retaining explicit Tauri origins (`tauri://localhost`, `http://tauri.localhost`, `https://tauri.localhost`).
- **Finding 3 (HSTS Preload & Cross-Origin Opener Isolation)**: `COMMON_SECURITY_HEADERS` in `website/server.mjs` lacked `Strict-Transport-Security` and `Cross-Origin-Opener-Policy`.
  - **Remediation Implemented**: Added `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload` and `Cross-Origin-Opener-Policy: same-origin-allow-popups` to `COMMON_SECURITY_HEADERS`.

## 2026-10-23 — Daily Defensive White-Hat Security Audit & Auto-Remediation Pass (8 Vulnerabilities Remediated)
- **Vuln 1 (Live Stripe API Calls & Secret Exposure During Automated Testing)**: When running `npm test` in `sweepr_crm`, undefined `NODE_ENV` loaded `.env` containing production `sk_live_...` secrets, and `getStripeForProject` instantiated real Stripe clients regardless of the `stripe: null` mock passed to `buildApp`. This triggered live `stripe.paymentIntents.create` API requests during unit tests and caused assertion failures.
  - **Remediation Implemented**: In `sweepr_crm/src/stripe.ts`, added guard `if (process.env.NODE_ENV === "test" && fallbackStripe === null) return null;`, explicitly set `process.env.NODE_ENV = "test"` across `test/multi-project-crm.test.ts` and `test/v1-licensing.test.ts`. All 18 automated suite tests now pass deterministically with zero live network calls.
- **Vuln 2 (SSRF / Credential Exfiltration Path in Tunnel Engine)**: `is_allowed_api_url` in `crates/sweepr-tunnel/src/lib.rs` blindly accepted any URL starting with `https://`, allowing potential override of `SWEEPR_API_URL` to send user license keys, emails, and WireGuard public keys to attacker-controlled external HTTPS endpoints.
  - **Remediation Implemented**: Hardened `is_allowed_api_url` to parse the host and strictly permit verified SWEEPR domains (`sweeprvpn.com`, `www.sweeprvpn.com`, `api.sweeprvpn.com`) plus localhost only when `allow_local` is active. Added unit test vector assertions in `crates/sweepr-tunnel/src/lib.rs`.
- **Vuln 3 (Arbitrary External URL Opening via WebView IPC in Desktop App)**: In `desktop-client/SweeprVpnApp.cs:463-475`, the `openCheckout` message handler parsed raw substring URLs matching `https://` and passed them directly to `Process.Start` with `UseShellExecute = true`, allowing potential arbitrary URL execution.
  - **Remediation Implemented**: Enforced defensive domain validation checking that `targetUrl` begins strictly with `https://sweeprvpn.com/` or `https://www.sweeprvpn.com/`, defaulting to `https://sweeprvpn.com/order`. Recompiled `SweeprVpnApp.exe` and refreshed `website/SWEEPRVPN.exe`.
- **Vuln 4 (Search-Path Hijacking / Binary Planting via Bare System Commands)**: `desktop-client/SweeprVpnApp.cs` invoked bare `"arp"` and `apps/desktop-tauri/src-tauri/src/lib.rs` invoked bare `"reg"` without absolute system paths, which on Windows could allow search-path binary planting if a rogue `arp.exe` or `reg.exe` existed in the working directory.
  - **Remediation Implemented**: Qualified `Path.Combine(Environment.SystemDirectory, "arp.exe")` in C# and `%SystemRoot%\System32\reg.exe` in Rust.
- **Vuln 5 (Static JSON File Exposure Risk in Web Root)**: In `website/server.mjs`, `.json` was in `ALLOWED_STATIC_EXTENSIONS`. Although known internal files were in `BLOCKED_STATIC_FILES`, any newly generated or temporary JSON state file in `website/` could be served over HTTP. The website frontend solely consumes `/api/...` endpoints and never requires raw static JSON files.
  - **Remediation Implemented**: Removed `.json` from `ALLOWED_STATIC_EXTENSIONS`. Direct requests to any `.json` file now return `404 Not Found` by default.
- **Vuln 6 (Missing CSRF / Cross-Origin Validation on Authenticated Customer Portal Actions)**: While session cookies used `SameSite=Lax`, state-changing endpoints (`POST /api/portal/purchase-addon`, `POST /api/portal/cancel-subscription`, `POST /api/portal/reactivate-subscription`, `POST /api/logout`) did not check `Sec-Fetch-Site` or validate `Origin` against trusted origins.
  - **Remediation Implemented**: Created `isSameOriginOrTrusted(req)` in `website/server.mjs` (matching `sweepr_crm`'s defense) to inspect Fetch Metadata (`Sec-Fetch-Site: cross-site`) and cross-site `Origin` headers, rejecting unauthorized cross-site requests with `403 Forbidden`.
- **Vuln 7 (Customer Email Enumeration on `/api/vpn/resend-key`)**: `/api/vpn/resend-key` returned `404 not_found` when an email did not exist, allowing adversaries to harvest which email addresses have active SWEEPR VPN subscriptions.
  - **Remediation Implemented**: Replaced asymmetric error responses with a uniform, generic confirmation (`200 OK`) stating "If an active SWEEPR VPN subscription is registered to ..., we have sent your activation code & license details."
- **Vuln 8 (Ephemeral Session Secret Invalidating Customer Logins on Server Restarts)**: `SESSION_SECRET` in `website/server.mjs` defaulted to `crypto.randomBytes(32)` if unset in `.env`, invalidating all active customer sessions upon container restart or deployment.
  - **Remediation Implemented**: Implemented stable cryptographic key derivation falling back to HMAC-SHA256 of `LICENSE_PRIVATE_KEY_B64` or `CRM_ADMIN_PASSWORD`, preserving session persistence across server restarts while maintaining 256-bit entropy.

## 2026-10-24 — Daily Defensive White-Hat Security Audit & Auto-Remediation Pass (8 Vulnerabilities Remediated)
- **Vuln 1 (Critical Auth Bypass & License Key Disclosure on `/checkout/success`)**: In `website/server.mjs`, when `accountId` was supplied in the query string without `subscription_id` or `session_id`, the handler bypassed Stripe subscription verification completely and fell through to signing a new authenticated session cookie (`sweepr_session`) and rendering `renderCheckoutSuccessPage(acc)` which displayed the victim's unmasked license key, activation code, and email address.
  - **Remediation Implemented**: Enforced mandatory `subscription_id` or `session_id` in `GET /checkout/success`. Direct requests lacking verifiable payment parameters are immediately rejected with `302 /order?error=payment_incomplete`. Subscriptions are authoritatively validated against Stripe to confirm `active` or `trialing` status and verify matching `metadata.account_id`.
- **Vuln 2 (Missing CSRF / Cross-Origin Validation on Authenticated Customer Portal Action `/api/billing-portal`)**: In `website/server.mjs`, while `/api/portal/purchase-addon`, `/api/portal/cancel-subscription`, and `/api/logout` enforced `isSameOriginOrTrusted(req)`, `POST /api/billing-portal` lacked cross-origin validation, allowing cross-site requests to initiate Stripe billing portal sessions.
  - **Remediation Implemented**: Added strict `isSameOriginOrTrusted(req)` verification across both `POST` and `GET` methods on `/api/billing-portal`, returning `403 Forbidden (cross-site)` for untrusted cross-origin requests.
- **Vuln 3 (Arbitrary External URL Opening via Native Opener IPC in Desktop & Web UI)**: In `apps/desktop-tauri/ui/index.html`, `desktop-client/app-ui.html`, and `website/app-preview.html`, the `postNative('openCheckout', payload)` IPC handler opened arbitrary URLs matching `payload.startsWith('https://')` via `tauri.opener.openUrl()`, which could allow arbitrary external URL execution in the user's default browser.
  - **Remediation Implemented**: Enforced strict domain prefix matching in `postNative('openCheckout', payload)` across all three files: strictly permitting `https://sweeprvpn.com/` and `https://www.sweeprvpn.com/`, defaulting to `https://sweeprvpn.com/order`. Recompiled `desktop-client/SweeprVpnApp.exe` and refreshed `website/SWEEPRVPN.exe`.
- **Vuln 4 (Search-Path Hijacking / Binary Planting via Bare System Commands in `sweepr-tunnel` & `sweepr-wifi-radar`)**: `crates/sweepr-tunnel/src/lib.rs` invoked bare `"powershell"` (with elevated `-Verb RunAs` privileges!), `"sc"`, and `"curl.exe"`, while `crates/sweepr-wifi-radar/src/neighbours.rs` invoked bare `"arp"`. On Windows, bare commands search the working directory first, opening binary planting vectors if rogue executables exist in the application folder.
  - **Remediation Implemented**: Qualified `powershell_bin()`, `sc_bin()`, and `curl_bin()` in `crates/sweepr-tunnel/src/lib.rs` to `%SystemRoot%\System32\...` and qualified `arp_bin()` in `crates/sweepr-wifi-radar/src/neighbours.rs` to `%SystemRoot%\System32\arp.exe`.
- **Vuln 5 (Insecure Cryptographic Ed25519 Token Verification Fallback in Desktop & Web UI)**: In `apps/desktop-tauri/ui/index.html`, `desktop-client/app-ui.html`, and `website/app-preview.html`, `verifySignedLicenseToken()` fell back to `return parts[2].length >= 80;` when WebCrypto was unavailable, which accepted any forged JWT containing an 80-character dummy signature string.
  - **Remediation Implemented**: Removed the length-only fallback; verification now strictly fails closed (`return false;`) whenever cryptographic verification cannot be authoritatively completed.
- **Vuln 6 (Key Existence Oracle / Asymmetric Response Status on `/v1/license/verify-key`)**: In `sweepr_crm/src/app.ts`, when a license key did not exist in the database, the endpoint returned HTTP 200 `{ valid: false, error: "key_not_found" }`. When a key existed but the supplied email did not match, it returned HTTP 401 `{ valid: false, error: "key_not_found" }`. This status asymmetry allowed adversaries to probe whether keys existed by supplying mismatched emails.
  - **Remediation Implemented**: Unified error responses to return a uniform HTTP 200 `{ valid: false, error: "key_not_found", project_id: projectId }` in both cases, eliminating the oracle.
- **Vuln 7 (Unconditional Localhost API Endpoint Querying in Release Web/Tauri UI)**: In `apps/desktop-tauri/ui/index.html`, `desktop-client/app-ui.html`, and `website/app-preview.html`, license activation and WireGuard configuration routines unconditionally pushed loopback addresses (`http://127.0.0.1:8788`, `http://127.0.0.1:8080`), allowing rogue local processes to spoof responses when remote network access was unavailable.
  - **Remediation Implemented**: Guarded loopback endpoints so they are only queried in explicit local development environments (`location.hostname === 'localhost' || location.hostname === '127.0.0.1'`).
- **Vuln 8 (Short-Code Activation Rate-Limiting & Verification Consistency)**: Verified and unified rate-limiting and validation rules across `sweepr_crm/src/app.ts` (`handleLicenseActivate`, `handleVerifyKey`), ensuring 6-digit short codes strictly require account email or verified service credentials, and are bounded by `portalTargetLimiter` lockout rules.
