## 2026-10-29 — Daily Defensive White-Hat Security Audit & Auto-Remediation Pass (7 Vulnerabilities Remediated)
- **Vuln 1 (CORS Origin: null Reflection on `/api/vpn/` Endpoints)**: In `website/server.mjs`, `resolveTrustedOrigin` contained `if (rawOrigin === 'null' && String(req?.url || '').startsWith('/api/vpn/')) return 'null';`. When reflected into `Access-Control-Allow-Origin: null`, any untrusted sandboxed iframe (`sandbox="allow-scripts"`), `data:` URI context, or local HTML file on an external site could issue cross-origin requests and read sensitive JSON responses from `/api/vpn/` endpoints (WireGuard credentials, license verification status, and device metadata).
  - **Remediation Implemented**: Removed the `null` reflection clause in `website/server.mjs`. If `rawOrigin === 'null'`, the origin resolver now falls back strictly to `PUBLIC_URL`, disallowing sandboxed iframe CORS access.
- **Vuln 2 (Dual-Stack IPv6 WireGuard Leak & Incomplete AllowedIPs Specification)**: In `website/server.mjs` (`POST /api/vpn/connect`, `POST /api/vpn/wireguard-config`), `crates/sweepr-tunnel/src/lib.rs`, and `desktop-client/SweeprVpnApp.cs`, default `allowed_ips` / `AllowedIPs` was set to `"0.0.0.0/0"` omitting the IPv6 default route `::/0`. On dual-stack IPv4/IPv6 networks, client OS networking routes IPv6 traffic (including major destinations like Google, YouTube, Cloudflare, and IPv6 DNS lookups) over clearnet outside the WireGuard tunnel.
  - **Remediation Implemented**: Enforced `0.0.0.0/0, ::/0` across `website/server.mjs`, `crates/sweepr-tunnel/src/lib.rs`, and `desktop-client/SweeprVpnApp.cs`. When `lan_bypass` is active, routed global IPv6 (`2000::/3`) through the tunnel while preserving local IPv6 addresses (`fe80::/10`, `fc00::/7`).
- **Vuln 3 (Search-Path Hijacking / Binary Planting via Bare System Commands in Desktop Tauri & C# Client)**:
  - In `apps/desktop-tauri/src-tauri/src/lib.rs`, `set_kill_switch` and `set_smart_tv_shields` invoked bare `"cmd"`, `"powershell"` (with elevated `-Verb RunAs` privileges!), `"netsh"`, and `"ipconfig"`.
  - In `desktop-client/SweeprVpnApp.cs`, `RunProcessCapture` and `RunHelperCmd` executed bare `"msiexec.exe"`, `"icacls.exe"`, `"sc.exe"`, `"netsh.exe"`, `"ipconfig.exe"`, and `"schtasks.exe"`.
  - On Windows, unqualified binary calls search the current working directory first before system paths, introducing Local Privilege Escalation (LPE) vectors if rogue binaries are present in the application folder.
  - **Remediation Implemented**: Fully qualified all system command invocations to `%SystemRoot%\System32\...` and `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe` in `apps/desktop-tauri/src-tauri/src/lib.rs` and dynamically resolved `Path.IsPathRooted(exe) ? exe : Path.Combine(Environment.SystemDirectory, exe)` in `SweeprVpnApp.cs`. Recompiled `desktop-client/SweeprVpnApp.exe` and refreshed `website/SWEEPRVPN.exe`.
- **Vuln 4 (Stripe Subscription Ownership Verification Bypass on `/api/confirm-subscription` & `/checkout/success`)**: In `website/server.mjs`, the condition `if (sub.metadata?.account_id && accountId && sub.metadata.account_id !== accountId)` evaluated to false when an adversary omitted `accountId` in the request body or query parameter. This allowed an attacker possessing a known subscription ID (`sub_1...`) to sign an authenticated `sweepr_session` cookie and extract the victim's full license key and 6-digit activation code.
  - **Remediation Implemented**: Enforced mandatory account matching whenever `sub.metadata?.account_id` is present on a subscription: requests must provide a matching `accountId` or hold an authenticated session cookie matching `sub.metadata.account_id`. Unauthenticated or mismatched requests fail closed with HTTP 403 / 302 redirect.

An adversary on an external website could trigger cross-origin POST requests to revoke devices or delete the victim's subscription account.
  - **Remediation Implemented**: Added `if (req.headers.cookie && !isSameOriginOrTrusted(req)) return sendJson(res, 403, { ok: false, error: 'forbidden_cross_site' }, {}, req);` across both endpoints.
- **Vuln 6 (Insecure Relative URL Opening via Native Opener IPC in Desktop Apps)**: In `apps/desktop-tauri/ui/index.html` and `desktop-client/app-ui.html`, `downloadAppleMobileConfigModal()` constructed relative URLs (`/api/vpn/apple-mobileconfig?...`) when served over `http:` / `https:` (such as `http://tauri.localhost`). Passing relative URLs to `tauri.opener.openUrl` or `postNative('openCheckout')` caused `SweeprVpnApp.cs` to reject the URL as non-matching and fall back to `/order`, while `tauri.opener.openUrl` failed to launch the download in the OS default browser.
  - **Remediation Implemented**: Hardened `downloadAppleMobileConfigModal()` in both files to construct and pass canonical absolute HTTPS URLs (`https://sweeprvpn.com/api/vpn/apple-mobileconfig?...`) to native openers.
- **Vuln 7 (Android Dual-Stack IPv6 DNS Leak on Mobile Networks)**: In `apps/mobile-android/app/src/main/java/com/sweepr/vpn/SweeprWireGuardVpnService.kt`, `establishTunInterface` only registered IPv4 DNS servers (`1.1.1.1` / `1.1.1.2`). On dual-stack cellular and Wi-Fi networks, the Android system resolver fell back to the carrier/ISP's native unencrypted IPv6 DNS servers.
  - **Remediation Implemented**: Added zero-log IPv6 DNS servers (`2606:4700:4700::1111` / `2606:4700:4700::1112`) and explicit `/128` TUN routes to `VpnService.Builder`, preventing clearnet IPv6 DNS fallback.

- **Vuln 6 (Unconfigured Google Play In-App Purchase Verification Bypass)**: In `website/server.mjs`, `POST /api/vpn/google-play/verify` returned a synthetic success response granting 365 days of Pro status if `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` was not configured in production.

- **Vuln 7 (Local Privilege Escalation / Search-Path Hijacking in Elevated Windows Commands)**: In `crates/sweepr-tunnel/src/lib.rs`, `bring_tunnel_up` and `bring_tunnel_down` invoked bare `"cmd.exe"`, `"netsh"`, and `"ipconfig"` inside elevated `Start-Process` PowerShell calls. Unqualified binary calls on Windows search the current working directory first, introducing search-path binary planting vectors under elevated privilege.
  - **Remediation Implemented**: Defined `cmd_bin()`, `netsh_bin()`, and `ipconfig_bin()` resolving explicitly to `%SystemRoot%\System32\` and passed fully qualified system paths to elevated `Start-Process`.
- **Vuln 8 (Untrusted WireGuard Binary Planting & Authenticode Signature Verification)**: In `desktop-client/SweeprVpnApp.cs`, `RunElevatedConnect` copied `wireguard.exe` and `wg.exe` from `wg_extract` to `C:\Program Files\WireGuard\` and extracted MSIs without cryptographically verifying Authenticode digital signatures.
  - **Remediation Implemented**: Added `IsValidWireGuardSignature` using PowerShell `Get-AuthenticodeSignature` to strictly verify that WireGuard binaries are signed by Jason A. Donenfeld / WireGuard before copying or execution. Recompiled `SweeprVpnApp.exe` and refreshed `website/SWEEPRVPN.exe`.

- **Vuln 10 (Sensitive Account Identification Disclosure in Self-Service Portal)**: In `sweepr_crm/src/app.ts`, `POST /v1/license/portal-lookup` querying with a high-entropy license key returned unmasked internal `account_id` and raw 6-digit `activation_code`.
