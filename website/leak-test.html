How to Check WebRTC Leak Online & Stop Browser STUN IP Exposure

Direct Answer: When you check WebRTC leak online using the diagnostic above, our browser sandbox queries a Session Traversal Utilities for NAT (STUN) candidate listener via RTCPeerConnection. If your browser returns a srflx (Server Reflexive) UDP candidate matching your home ISP IPv4 or IPv6 address while a VPN extension is active, your real IP and location are leaking.

1. Chrome, Edge & Brave WebRTC Fix

Browser proxy extensions only tunnel TCP HTTP traffic, leaving UDP STUN ports open. Running the native SWEEPR VPN WireGuard Kernel Tunnel binds all UDP/TCP sockets at the OS NDIS/nftables layer so STUN requests never bypass the VPN.

2. Firefox media.peerconnection.enabled

In Mozilla Firefox, open about:config and set media.peerconnection.ice.default_address_only = true and media.peerconnection.ice.no_host = true, or route system-wide via SWEEPR VPN (10.66.0.1).

3. Transparent ISP DNS Hijacking Check

UK and US ISPs (Virgin Media, BT, Sky, TalkTalk, Comcast) intercept port 53 DNS lookups. SWEEPR VPN forces all DNS queries inside the ChaCha20-Poly1305 WireGuard tunnel to our RAM-only resolver at 10.66.0.1.
