1. Reading ARP/NDP Tables & Decoding IEEE OUI Prefixes

Every active Wi-Fi client on your subnet must answer Layer-2 Address Resolution Protocol (ARP) for IPv4 or Neighbor Discovery Protocol (NDP) for IPv6. The first three octets of a hardware MAC address form the IEEE OUI (Organizationally Unique Identifier), revealing the exact wireless chip vendor inside headless smart-home gadgets even when hostnames are blank:

# Windows & macOS — Read local IPv4 ARP cache
arp -a

# Linux — Inspect IPv4 ARP and IPv6 NDP neighbor tables simultaneously
ip -4 neigh show && ip -6 neigh show

# Common IEEE OUI prefixes you will spot on home subnets:
# EC:FA:BC / 24:6F:28 -> Espressif Inc. (ESP8266 / ESP32 smart plugs, LED controllers)
# B8:27:EB / DC:A6:32 -> Raspberry Pi Foundation
# 44:07:0B / F4:F5:D8 -> Google Nest / Chromecast
# Note: If the 2nd hex character of the 1st byte is 2, 6, A, or E (e.g. D2:..),
# the MAC is locally administered (randomized iOS/Android/Windows Private Wi-Fi Address).

2. Discovering Silent Devices via mDNS (_googlecast, _hap, _airplay)

Headless ESP32 outlets, IP cameras, printers, and streaming receivers frequently ignore unsolicited ICMP pings, making basic nmap sweeps unreliable without elevated privileges. However, nearly all consumer devices broadcast multicast DNS (mDNS UDP port 5353) and SSDP announcements describing their services:

# Linux (Avahi) / macOS (dns-sd) — Enumerate active LAN service types
avahi-browse -art | grep -E "(_googlecast|_hap|_airplay|_rtsp)"
dns-sd -B _services._dns-sd._udp local.

# Manual nmap comparison (requires elevated privileges for raw ARP)
sudo nmap -sn 192.168.1.0/24

Home Wi-Fi Device Discovery FAQs

How can I distinguish an unknown intruder from my own iPhone using Private Wi-Fi Address?

Check the second hex digit of the MAC address's first byte. If it is 2, 6, A, or E (for example 3A:8F:...), the locally administered bit is set, indicating OS MAC randomization rather than a physical hardware vendor OUI.

Why do smart plugs and IP cameras stay hidden from basic ping commands?

Embedded IoT firmware often drops ICMP Echo packets or sleeps between Wi-Fi DTIM beacons. Layer-2 ARP/NDP caches paired with mDNS (_hap, _googlecast, _airplay) and SSDP queries wake and identify them reliably.
