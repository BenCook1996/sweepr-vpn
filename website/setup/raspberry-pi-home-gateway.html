1. Static LAN IP & dnsmasq DHCP Option 3 Router Injection

On Debian Bookworm (64-bit Raspberry Pi OS), give onboard Gigabit Ethernet eth0 a static LAN address such as 192.168.1.2/24 pointing upstream to your ISP hub at 192.168.1.1. You then choose between two clean topology modes:

  • Targeted Smart-TV Mode (Zero ISP Hub Changes): Keep DHCP enabled on your ISP hub, then edit only your Samsung/LG/Sony TV network settings manually to Gateway: 192.168.1.2 and DNS: 192.168.1.2.
  • Whole-LAN DHCP Takeover via dnsmasq: Disable DHCP on your ISP hub and let dnsmasq on the Pi hand out leases injecting dhcp-option=3,192.168.1.2 (default router) and dhcp-option=6,192.168.1.2 (ACR-filtered DNS forwarded upstream to 10.66.0.1).
/etc/dnsmasq.d/sweepr-gateway.conf & nmcli Static IP
sudo nmcli con mod "Wired connection 1" ipv4.addresses 192.168.1.2/24   ipv4.gateway 192.168.1.1 ipv4.dns "1.1.1.1" ipv4.method manual

# Optional whole-LAN DHCP takeover (/etc/dnsmasq.d/sweepr-gateway.conf):
interface=eth0
dhcp-range=192.168.1.50,192.168.1.220,255.255.255.0,12h
dhcp-option=3,192.168.1.2
dhcp-option=6,192.168.1.2
server=10.66.0.1
no-resolv

2. Persistent nftables Masquerade & Pi 5 vs. Pi 4 Throughput

Enable kernel IPv4 packet forwarding permanently and configure nftables to masquerade LAN client packets onto wg0 with automatic MSS clamping (solving the "one-arm router" hairpinning quirk on a single Ethernet cable): 

echo "net.ipv4.ip_forward=1" | sudo tee /etc/sysctl.d/99-pi-gateway.conf
sudo sysctl -p /etc/sysctl.d/99-pi-gateway.conf

cat <<'EOF' | sudo tee /etc/nftables.conf
flush ruleset
table inet sweepr_gw {
  chain forward {
    type filter hook forward priority 0; policy drop;
    iifname "eth0" oifname "wg0" accept
    iifname "wg0" oifname "eth0" ct state related,established accept
    tcp flags syn tcp option maxseg size set rt mtu
  }
  chain postrouting {
    type nat hook postrouting priority 100; policy accept;
    oifname "wg0" masquerade
  }
}
EOF
sudo systemctl enable --now nftables wg-quick@wg0

Raspberry Pi Gateway Questions

Do I need a second USB Ethernet dongle for a Raspberry Pi VPN gateway?

No. Single-interface "router-on-a-stick" forwarding over onboard Gigabit Ethernet handles 450+ Mbps duplex cleanly while letting you plug straight into any free LAN switch port on your ISP hub.

Why must dnsmasq specify server=10.66.0.1 and no-resolv?

Without no-resolv, dnsmasq reads /etc/resolv.conf and forwards IoT TV DNS queries back toward your ISP hub rather than inside the encrypted wg0 tunnel.

How do I prevent ICMP redirect warnings in one-arm LAN routing?

Add net.ipv4.conf.all.send_redirects=0 and net.ipv4.conf.eth0.send_redirects=0 inside /etc/sysctl.d/99-pi-gateway.conf so the Pi never tells LAN hosts to bypass it back to the ISP hub.
