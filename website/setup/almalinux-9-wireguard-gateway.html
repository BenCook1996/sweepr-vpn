EL9 Kernel WireGuard vs. User-Space Tunnel Daemons

RHEL 9, AlmaLinux 9, and Rocky Linux 9 compile the upstream wireguard driver directly inside kernel 5.14.0-x.el9. Unlike legacy OpenVPN installations that bounce every packet across the tun character device into user space, WireGuard executes ChaCha20-Poly1305 encryption inside kernel softirq queues across multiple CPU cores.

1. Install wireguard-tools & Import via NetworkManager

Only user-space control utilities are absent from the base AppStream repository. Pull wireguard-tools from EPEL, place your downloaded SWEEPR profile inside /etc/wireguard/, restore SELinux contexts, and hand tunnel lifecycle control to NetworkManager so systemd ordering remains deterministic across reboots.

sudo dnf install -y epel-release
sudo dnf install -y wireguard-tools
sudo install -m 600 ~/sweepr-ams01.conf /etc/wireguard/sweepr-ams01.conf
sudo restorecon -Rv /etc/wireguard
sudo nmcli connection import type wireguard file /etc/wireguard/sweepr-ams01.conf
sudo nmcli connection modify sweepr-ams01 ipv4.dns "10.64.0.1" ipv4.ignore-auto-dns yes
sudo nmcli connection up sweepr-ams01

Avoid running both wg-quick@wg0.service and a NetworkManager-imported connection for the same tunnel simultaneously; pick nmcli on multi-NIC gateways managed by RHEL cockpit or Ansible.

2. Kernel Forwarding, firewalld Masquerade & MSS Clamping

To turn the AlmaLinux box into a transparent subnet gateway for downstream switches or KVM guests, enable IPv4 forwarding persistently, disable strict reverse-path filtering on asymmetric dual-homed interfaces, and bind firewalld masquerading onto the tunnel zone.

cat <<'EOF' | sudo tee /etc/sysctl.d/99-sweepr-gateway.conf
net.ipv4.ip_forward = 1
net.ipv4.conf.all.rp_filter = 2
net.ipv4.conf.default.rp_filter = 2
EOF
sudo sysctl --system

sudo firewall-cmd --zone=external --add-interface=sweepr-ams01 --permanent
sudo firewall-cmd --zone=external --add-masquerade --permanent
sudo firewall-cmd --zone=internal --add-interface=enp2s0 --permanent
sudo firewall-cmd --permanent --direct --add-rule ipv4 filter FORWARD 0   -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --clamp-mss-to-pmtu
sudo firewall-cmd --reload

On UK FTTP circuits running PPPoE upstream of your AlmaLinux server, forcing TCPMSS --clamp-mss-to-pmtu stops large TLS ServerHello frames from blackholing behind 1492-byte ISP framing.

3. Verifying Handshakes & Preventing Cleartext WAN Leaks

Confirm active peer counters with sudo wg show and verify that packets leaving your LAN NIC hit the encrypted tunnel rather than falling back onto enp1s0 if the peer endpoint pauses.

sudo wg show sweepr-ams01
ip route get 1.1.1.1
sudo nft list ruleset | grep -A4 masquerade

AlmaLinux 9 & Rocky Linux 9 Operations FAQ

Why does nmcli fail to load /etc/wireguard/*.conf under SELinux enforcing?

Files moved from a user home directory retain user_home_t labels. Running restorecon -Rv /etc/wireguard or copying directly with install -m 600 resets the label to etc_t so NetworkManager reads keys cleanly without disabling SELinux.

Should I use rp_filter=2 on a dual-homed EL9 VPN router?

Yes. RHEL 9 defaults to strict reverse-path validation (rp_filter=1), which silently drops forwarded LAN return traffic whenever policy routes send outbound packets via sweepr-ams01 while local probes arrive on enp2s0.

Can I keep SSH reachable on the public NIC while routing outbound traffic through WireGuard?

Yes. Add an explicit source-policy lookup rule for your WAN NIC gateway IP (ip rule add from <WAN_IP> table 100) or use AllowedIPs excluding your management subnet so inbound SSH replies leave via the original Ethernet path.
