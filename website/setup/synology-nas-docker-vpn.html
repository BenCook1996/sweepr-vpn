1. Creating /dev/net/tun on Boot & Docker Compose Stack

Synology DSM 7.2 omits /dev/net/tun after cold boots unless created explicitly. Before launching Container Manager Projects, open Control Panel → Task Scheduler → Create → Triggered Task → User-defined script, set Event to Boot-up as root, and paste the TUN node initializer below, then run it once immediately.

DSM Boot Script + Hardened Gluetun docker-compose.yml
# 1) DSM Task Scheduler (Boot-up, root):
mkdir -p /dev/net
[ -c /dev/net/tun ] || mknod /dev/net/tun c 10 200
chmod 600 /dev/net/tun

# 2) Container Manager Project (docker-compose.yml):
services:
  gluetun:
    image: qmcgaw/gluetun:v3
    container_name: gluetun
    cap_add: [NET_ADMIN]
    devices: [/dev/net/tun:/dev/net/tun]
    ports:
      - "8080:8080" # Expose sibling container WebUI safely on LAN
    environment:
      - VPN_SERVICE_PROVIDER=custom
      - VPN_TYPE=wireguard
      - WIREGUARD_PUBLIC_KEY=<SWEEPR_AMS01_PUBKEY>
      - WIREGUARD_PRIVATE_KEY=<NAS_CLIENT_PRIVATE_KEY>
      - WIREGUARD_ENDPOINT_IP=95.179.181.53
      - WIREGUARD_ENDPOINT_PORT=51820
      - WIREGUARD_ADDRESSES=10.64.0.2/32
      - WIREGUARD_MTU=1420
      - DNS_ADDRESS=10.64.0.1
      - FIREWALL_VPN_INPUT_PORTS=8080
      - FIREWALL_OUTBOUND_SUBNETS=192.168.1.0/24
    restart: unless-stopped

  archiver:
    image: lscr.io/linuxserver/aria2:latest
    network_mode: "service:gluetun"
    depends_on: [gluetun]
    restart: unless-stopped

Notice that sibling containers attached via network_mode: "service:gluetun" must declare their ports: on the gluetun service block itself—Docker forbids port mappings on containers sharing another container's network namespace.

Synology DSM & Gluetun WireGuard FAQ

Why does Gluetun log TUN device missing right after a DSM update?

DSM upgrades clear /dev/net/tun until your root Task Scheduler boot script runs again. Re-run that triggered task or reboot once after applying DSM patches.

Why is my sibling container WebUI unreachable from my laptop on LAN?

Confirm two things: the port is mapped on the gluetun container rather than the sibling service, and FIREWALL_OUTBOUND_SUBNETS matches your actual home LAN CIDR (e.g., 192.168.1.0/24 or 10.0.0.0/24).

Does Gluetun WireGuard work on Synology NAS models without kernel wireguard.ko?

Yes—Gluetun embeds WireGuard user-space/TUN support directly inside the container using /dev/net/tun, working cleanly without DSM host kernel modules.
