1. Package Install & tun_wg0 Interface Assignment

pfSense Plus / CE Procedure

Navigate to System → Package Manager → Available Packages and install WireGuard. Under VPN → WireGuard → Tunnels, add tun_wg0 with your SWEEPR PrivateKey, then enter Peers with Endpoint port 51820, Keepalive 25, and AllowedIPs = 0.0.0.0/0. Assign tun_wg0 under Interfaces → Assignments and set static IPv4 10.64.0.2/32 plus MSS = 1352.

OPNsense 24.x Procedure

Open System → Firmware → Plugins and install os-wireguard. Under VPN → WireGuard → Instances, tick Disable Routes (so policy rules dictate egress) and set Gateway IP to 10.64.0.1. Bind your peer, then assign wg0 in Interfaces → Assignments and restart WireGuard.

2. Outbound NAT, 10.64.0.1 Gateway Monitor & Multi-Queue RSS

Assigning tun_wg0 alone does not translate LAN source addresses or track tunnel availability. Complete these three firewall settings before steering LAN rules:

  • Hybrid / Manual Outbound NAT: Open Firewall → NAT → Outbound, choose Hybrid Outbound NAT rule generation, and add a mapping with Interface SWEEPR_WG, Source LAN net (or specific VLAN subnet), and Translation Interface Address.
  • Gateway Monitor IP = 10.64.0.1: Under System → Routing → Gateways, edit SWEEPR_GW and type 10.64.0.1 as the Monitor IP. Because WireGuard peer tunnel subnets do not expose arbitrary upstream ICMP gateways automatically, pinging 10.64.0.1 keeps dpinger telemetry green.
  • Kill-Switch Policy Tagging: On your LAN/VLAN pass rule that sets Gateway = SWEEPR_GW, enter tag NO_WAN_EGRESS, then create a Floating Reject rule on WAN outbound matching tagged NO_WAN_EGRESS packets so offline tunnels never leak onto ISP WAN.
  • Hardware Crypto vs. Multi-Queue RSS: Intel QAT and AES-NI offload AES-GCM, not ChaCha20-Poly1305. On multi-core Intel N100/Celeron/Xeon boxes, enable Receive Side Scaling (net.inet.rss.enabled="1" in System Tunables) so if_wg encryption fans out across every physical core.

pfSense & OPNsense WireGuard FAQ

Why does dpinger show 100% packet loss on my new tun_wg0 gateway?

Without an explicit Monitor IP, dpinger tries pinging your local tunnel interface or an unreachable link-local address. Setting Monitor IP to 10.64.0.1 resolves health checks cleanly inside the tunnel.

How do I prevent pfSense Unbound Resolver from leaking queries out WAN?

Under Services → DNS Resolver, bind Outgoing Network Interfaces exclusively to SWEEPR_WG or forward queries directly to 10.64.0.1 over the tunnel gateway.

Should I enable Hardware Checksum Offloading on virtualized pfSense/OPNsense?

Inside Proxmox or ESXi VMs using virtio NICs, disable hardware checksum offloading so encapsulated WireGuard UDP checksums do not silently drop inside the hypervisor bridge.
