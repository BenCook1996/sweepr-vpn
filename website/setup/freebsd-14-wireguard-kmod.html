FreeBSD 14.1 if_wg(4) Kernel Module vs. wireguard-go

FreeBSD 14 re-integrated the audited C implementation of if_wg directly into base /boot/kernel/if_wg.ko. Whereas wireguard-go copies packets through /dev/tun across Go userland goroutines, if_wg processes ChaCha20-Poly1305 encryption in kernel taskqueues across Intel igc/ix NIC queues.

1. Load if_wg at Boot & Configure /usr/local/etc/wireguard/wg0.conf

Install wireguard-tools from FreeBSD ports/pkg, persist the kernel module and gateway forwarding flags via sysrc, and create your interface definition with strict 0600 file permissions.

pkg install -y wireguard-tools
sysrc kld_list+="if_wg"
sysrc wireguard_enable="YES"
sysrc wireguard_interfaces="wg0"
sysrc gateway_enable="YES"
kldload if_wg

install -d -m 700 /usr/local/etc/wireguard
cat <<'EOF' > /usr/local/etc/wireguard/wg0.conf
[Interface]
PrivateKey = <BSD_GATEWAY_PRIVATE_KEY>
Address = 10.64.0.2/32
DNS = 10.64.0.1
MTU = 1420

[Peer]
PublicKey = <SWEEPR_LON01_PUBKEY>
Endpoint = lon01.wg.sweeprvpn.com:51820
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25
EOF
chmod 600 /usr/local/etc/wireguard/wg0.conf

2. Configure pf.conf NAT, MSS Scrubbing & Anti-Leak Drop Rules

FreeBSD's pf firewall handles outbound NAT onto wg0 while clamping TCP MSS so packets traversing PPPoE or encapsulated DSL links never fragment. Adding an explicit cleartext block on $ext_if prevents LAN subnets from leaking onto your ISP link if wg0 resets.

ext_if = "igc0"
lan_if = "igc1"
wg_if  = "wg0"
lan_net = "192.168.10.0/24"
wg_endpoint = "78.141.205.68"

set skip on lo0
scrub on $wg_if all max-mss 1352 no-df random-id
nat on $wg_if from $lan_net to any -> ($wg_if)

block drop out quick on $ext_if from $lan_net to any
pass out quick on $ext_if proto udp to $wg_endpoint port 51820 keep state
pass out quick on $wg_if from ($wg_if) to any keep state
pass in quick on $lan_if from $lan_net to any keep state

Validate rule syntax and start both subsystems: pfctl -nf /etc/pf.conf && service pf reload && service wireguard start, then inspect counters with wg show wg0 and pfctl -ss.

FreeBSD 14 WireGuard Questions

Why set max-mss 1352 in pf.conf alongside MTU 1420?

MTU 1420 governs outer WireGuard encapsulation over 1500-byte Ethernet, while clamping TCP SYN segments to max-mss 1352 inside pf gives headroom for PPPoE (1492) and VLAN tags so LAN clients never stall on PMTU blackholes.

Does pkg install wireguard-tools pull in Go dependencies?

No. When if_wg is loaded on FreeBSD 14, wireguard-tools ships only the lightweight C wg utility and wg-quick rc script without any Go runtime.

How can I verify LAN packets actually traverse wg0?

Run tcpdump -ni wg0 -c 10 while browsing from a LAN workstation, or check pfctl -vsq and netstat -I wg0 byte counters increasing monotonically.
