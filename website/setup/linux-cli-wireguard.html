1. Package Installation: Ubuntu/Debian, Arch & Fedora

Install wireguard-tools plus the DNS resolver helper matching your init stack. Without a resolver shim, wg-quick aborts on /usr/bin/resolvconf: command not found whenever your config declares DNS = 10.64.0.1. 

# Ubuntu 22.04/24.04 & Debian 12 (systemd-resolved or openresolv):
sudo apt update && sudo apt install -y wireguard-tools systemd-resolved

# Arch Linux (pacman):
sudo pacman -S --needed wireguard-tools systemd-resolvconf

# Fedora Workstation / Server (dnf):
sudo dnf install -y wireguard-tools

Split DNS Routing via systemd-resolved (resolvectl)

On modern Ubuntu, Fedora, and Arch desktops running systemd-resolved, make sure wg0 takes global DNS priority via the ~. routing domain so local ISP DHCP servers on wlan0 or enp3s0 never intercept queries in parallel. 

sudo install -m 600 ~/Downloads/sweepr-lon01.conf /etc/wireguard/wg0.conf
sudo systemctl enable --now wg-quick@wg0
sudo resolvectl dns wg0 10.64.0.1
sudo resolvectl domain wg0 "~."
resolvectl status wg0

3. Handshake Debugging with wg show & Leak Audits

Run sudo wg show wg0 to inspect live tunnel health. A healthy link prints a recent latest handshake (under 2 minutes) alongside non-zero received and sent byte counters. If received remains at 0 B, check firewall egress for UDP 51820 or test switching endpoint port to 443 and lowering MTU to 1380 on mobile tethering.

Linux WireGuard CLI Questions

Why does wg-quick fail with resolvconf: command not found on Ubuntu or Arch?

wg-quick invokes resolvconf whenever a DNS = line exists. Symlink resolvectl or install openresolv / systemd-resolvconf, or manage DNS directly via nmcli connection import.

Do Docker bridge containers break when wg-quick adds default table routes?

No—wg-quick uses policy routing via fwmark 51820 and suppress_prefixlength 0, keeping local RFC1918 and Docker bridge routes untouched on the main routing table.

How can I prevent IPv4/IPv6 leaks if wg0 stops unexpectedly?

Add PostUp and PreDown nft / iptables kill-switch rules rejecting non-tunnel outbound packets except UDP traffic addressed directly to your SWEEPR endpoint IP.
